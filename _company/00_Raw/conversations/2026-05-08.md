## kmongland 사이트 구축을 위한 MVP 구조 설계 및 기술 스택 리스트

CEO님의 지시에 따라, `kmongland`의 핵심 목표인 '사이트 구축'을 위한 최소 기능 제품(MVP)의 구조와 필요한 기술 스택을 설계했습니다. 이 MVP는 초기 학습 자료를 제공하고 커뮤니티 기반을 마련하는 데 중점을 둡니다.

### 1. MVP 목표 정의 (Goal Setting)
**핵심 목표:** 한국어 학습 콘텐츠를 효과적으로 전달하고, 사용자가 학습 과정을 체계적으로 따라올 수 있는 최소한의 인터페이스를 구축한다.

**MVP 기능 범위:**
1.  **콘텐츠 표시:** 학습 자료(레슨, 문법 설명 등)를 명확하게 보여주는 페이지.
2.  **사용자 인터페이스:** 기본적인 탐색 및 접근성을 제공하는 구조.
3.  **기본 반응성:** 모바일 환경에서 원활하게 작동하는 디자인.

### 2. MVP 아키텍처 설계 (Structure Design)
MVP는 빠른 개발과 배포를 위해 **풀스택(Full-Stack)** 접근 방식을 채택하되, 초기에는 프론트엔드 중심의 정적 사이트 생성 방식(SSG)을 고려하여 개발 속도를 높입니다.

**추천 아키텍처:** JAMstack 기반 (Static Site Generation + Headless CMS)

| 레이어 | 역할 | 기술 선택 근거 |
| :--- | :--- | :--- |
| **프론트엔드 (Presentation)** | 사용자에게 보이는 모든 UI 및 상호작용 처리. | React / Next.js 또는 Vue.js (빠른 개발, 컴포넌트 재사용성 높음) |
| **백엔드 (API/Logic)** | 데이터 관리, 인증(필요시), 콘텐츠 제공의 핵심 로직. | Next.js의 API Routes 또는 별도의 서버리스 함수 (초기 MVP는 프론트엔드 통합으로 최소화) |
| **데이터베이스 (Storage)** | 학습 자료, 사용자 진행 상황 등 동적 데이터 저장. | Markdown/JSON 파일 기반 초기 구성 후, 필요시 PostgreSQL 또는 MongoDB로 확장 고려. |
| **배포 및 호스팅 (Deployment)** | 웹사이트를 전 세계에 안정적으로 배포. | Vercel 또는 Netlify (JAMstack 환경에 최적화, CI/CD 용이) |

### 3. 필수 기술 스택 리스트 (Technology Stack List)

**A. 프론트엔드 (Frontend)**
*   **언어:** TypeScript (안정성 및 대규모 프로젝트 대비)
*   **프레임워크:** **Next.js (React 기반)** - 서버 컴포넌트와 API 기능을 통합하여 초기 MVP 구축 속도를 극대화합니다.
*   **스타일링:** Tailwind CSS - 빠른 반응형 UI 구현과 일관된 디자인 시스템 구축에 용이합니다.

**B. 백엔드 & 데이터 (Backend & Data)**
*   **CMS/데이터 관리:** Markdown 파일 또는 JSON 파일을 사용하여 초기 학습 콘텐츠를 구조화하고, 이를 프론트엔드가 읽어들이도록 설계합니다. (초기 MVP의 복잡도를 낮춤)
*   **API 연동:** 필요 시 Firebase (인증) 또는 Supabase (DB/Auth)를 활용하여 백엔드 구축 부담을 줄입니다.

**C. 인프라 및 배포 (Infrastructure & Deployment)**
*   **호스팅:** **Vercel** - Next.js 프로젝트에 대한 최고의 통합성과 자동 배포 환경을 제공합니다.
*   **버전 관리:** Git / GitHub

### 4. 다음 단계 제안 (Next Steps)
MVP 구축의 첫 단계로, 기술 스택을 확정하고 데이터 구조를 정의해야 합니다.

## 1. 브랜드 비주얼 시스템 (Visual System Foundation)

브랜드 정체성(한국어 교육, 자가학습 기반, 글로벌 타깃)을 반영하여 **신뢰감**과 **접근성**을 최우선으로 하는 미니멀하고 학술적인 디자인 시스템을 제안합니다.

### 1.1. 컬러 팔레트 (Color Palette)

교육 콘텐츠의 신뢰도를 높이고 학습 몰입도를 유지하기 위해 차분하면서도 명료한 색상을 사용합니다.

| 역할 | 색상 이름 | HEX 코드 | 용도 및 의미 |
| :--- | :--- | :--- | :--- |
| **Primary (주요)** | kmongland Blue | `#0056b3` | 신뢰, 지성, 안정감. 핵심 CTA(Call to Action) 및 주요 링크에 사용. |
| **Secondary (보조)** | Light Gray | `#f4f7fa` | 배경색. 학습 공간을 제공하여 콘텐츠에 집중하게 함. |
| **Accent (강조)** | Soft Orange | `#ff9851` | 활력, 주목, 성취감. 중요한 알림이나 진행률 표시(Progress Bar)에 사용. |
| **Neutral (보조 텍스트)** | Dark Gray | `#333333` | 본문 텍스트 및 제목. 높은 가독성 보장. |

### 1.2. 타이포그래피 시스템 (Typography System)

가독성과 전문성을 확보하기 위해 산세리프 계열의 폰트를 사용하여 모던하고 깔끔한 느낌을 강조합니다.

*   **Primary Font (제목/헤드라인):** **Pretendard Bold / Medium**
    *   **용도:** 브랜드 제목, 섹션 헤더 등 시각적 계층 구조 확립.
*   **Secondary Font (본문/내러티브):** **Pretendard Regular**
    *   **용도:** 학습 자료, 설명 텍스트 등 긴 콘텐츠의 가독성 극대화.

### 1.3. 레이아웃 및 그리드 원칙 (Layout & Grid Principles)

*   **여백 (Whitespace):** 충분한 여백을 사용하여 콘텐츠에 숨 쉴 공간을 제공합니다. 이는 복잡한 학습 내용을 시각적으로 분리하고 집중도를 높이는 핵심 요소입니다.
*   **그리드:** 12컬럼 기반의 그리드를 사용하되, 모바일 우선(Mobile-First) 접근 방식을 채택하여 모든 화면 크기에서 콘텐츠가 자연스럽게 재배치되도록 설계합니다.
*   **카드 디자인 (Card Design):** 학습 레슨이나 콘텐츠 단위는 명확한 경계선과 그림자(Soft Shadow)를 사용하여 독립된 모듈로 인식하게 하여 탐색 용이성을 높입니다.

## 2. 핵심 페이지 와이어프레임 방향 (Core Page Wireframe Direction)

MVP 구축을 위해 필수적인 세 가지 핵심 페이지에 대한 디자인 방향을 제시합니다.

### A. 홈 페이지 (Homepage / Landing Page) - **신뢰 구축 및 시작 유도**

| 섹션 | 목적 | 시각적 구현 방향 |
| :--- | :--- | :--- |
| **Hero Section** | 방문자에게 즉각적인 가치 전달 및 학습 시작 유도. | 중앙 정렬된 큰 헤드라인 (Primary Font) + kmongland Blue 강조 배경. 명확한 CTA 버튼 ("Start Learning Now"). |
| **Value Proposition** | kmongland가 제공하는 핵심 가치(Why us?) 제시. | 3~4개의 아이콘 기반 섹션으로 구성. 각 아이콘 옆에 Soft Orange 액센트 색상 사용. (예: 체계적 커리큘럼, 실용적인 자료, 글로벌 커뮤니티) |

| **Trust Builder** | 신뢰도 확보. | 실제 학습자 수, 완료된 레슨 수 등 간단한 통계 지표를 배치하여 사회적 증거 제공. |

### B. 콘텐츠/레슨 페이지 (Lesson Page) - **몰입도 극대화**

*   **레이아웃:** 좌측 또는 상단에 핵심 콘텐츠(영상 플레이어, 주요 문법 설명)를 배치하고, 우측에 보조 정보 및 학습 자료를 배치하는 2-컬럼 레이아웃을 채택합니다.
*   **학습 흐름 강조:** 각 섹션(문법 설명 $\rightarrow$ 예문 $\rightarrow$ 연습 문제)은 명확하게 구분되어야 합니다. (세로 스크롤 기반의 논리적 흐름 강조).
*   **상호작용:** 학습 진행 상황을 시각적으로 피드백하기 위해, 페이지 상단에 전체 커리큘럼 대비 현재 위치를 표시하는 **진행률 바(Progress Bar)**를 반드시 배치합니다.

### C. 시작하기/가입 페이지 (Onboarding / Sign-up Page) - **간소화된 진입 장벽**

*   **목표:** 사용자가 학습에 대한 부담 없이 빠르게 사이트에 참여하도록 유도.
*   **디자인:** 최대한 미니멀하게 구성합니다. 최소한의 입력 필드(이메일, 비밀번호 등)만 제시하고, 나머지 정보는 다음 단계에서 요청하는 방식으로 설계하여 이탈률을 최소화합니다.
*   **톤앤매너:** kmongland Blue를 사용하여 안정감을 주고, 필수 항목 외의 부가적인 설명은 간결한 텍스트로 처리합니다.

## 1. 핵심 데이터 모델 (Data Model)

사이트의 핵심 기능(학습 콘텐츠 관리, 사용자 경험 반영)을 위해 Markdown 형식으로 데이터 모델을 정의합니다. 이는 Next.js 프로젝트에서 사용될 JSON/Markdown 파일로 변환되어 개발 속도를 높입니다.

### `data_model.md`

```markdown
# Data Model for kmongland Website MVP

## 1. Content (학습 콘텐츠)
- **Content ID (UUID):** 고유 식별자
- **Title (제목):** 학습 모듈의 제목 (예: '기초 인사말 배우기')
- **Type (유형):** 콘텐츠 유형 (Lesson, Quiz, Grammar_Rule, Reading)
- **Level (수준):** 난이도 (Beginner, Intermediate, Advanced)
- **Content Body (본문):** 학습 내용 상세 설명 (Markdown 형식으로 저장)
- **Media Assets (미디어):** 관련 이미지/영상 링크 목록

## 2. User & Progress (사용자 및 진도 관리)
- **User ID:** 사용자 고유 식별자
- **Email / Username:** 사용자 식별 정보
- **Progress Tracking (진도 추적):** 콘텐츠별 학습 상태 (Completed: boolean, Score: number(0-100))
- **Enrollment Date (등록일):** 시작 일시

## 3. Design System Mapping (디자인 시스템 매핑)
- **Component:** 사용될 UI 컴포넌트 이름 (예: Card, Button, NavigationBar)
- **Style Reference:** 적용할 디자인 변수/스타일 참조 (예: color_primary, typography_h1)
- **Status:** 활성화 여부

## 4. API Endpoints Mapping (API 엔드포인트 매핑)
- **Endpoint Path:** RESTful 경로 (예: /api/content/[id], /api/user/progress)
- **Method:** HTTP 메소드 (GET, POST, PUT, DELETE)
- **Description:** 해당 엔드포인트의 기능 설명
```

## 2. 초기 파일 구조 (Initial File Structure)

Next.js와 Tailwind CSS를 기반으로 디자인 시스템과 데이터 모델을 반영한 최소 기능 제품(MVP) 초기 파일 구조를 생성합니다.

### `src/` 디렉토리 구조

```
src/
├── app/                      # Next.js App Router 기본 폴더
│   ├── (main)/              # 메인 레이아웃 그룹
│   │   ├── page.tsx         # 홈 페이지 (Landing Page)
│   │   └── layout.tsx       # 메인 레이아웃 (Header, Footer 포함)
│   ├── api/                 # API 라우트 폴더 (선택 사항)
│   └── globals.css         # 전역 스타일 및 Tailwind 설정
├── components/              # 재사용 가능한 UI 컴포넌트
│   ├── ui/                  # Atomic Design 기반 기본 요소 (Button, Input 등)
│   │   ├── Button.tsx
│   │   └── Card.tsx
│   └── layout/              # 페이지별 레이아웃 컴포넌트
│       ├── Header.tsx
│       └── Footer.tsx
├── data/                    # 데이터 모델 및 초기 데이터 저장소
│   ├── content.json         # 1. Content 데이터 저장
│   └── user_data.json       # 2. User Progress 데이터 저장
├── lib/                     # 유틸리티, API 클라이언트, 설정 파일
│   ├── api.ts               # 외부 API 통신 함수 정의
│   ├── data_schema.ts       # 데이터 모델(JSON 스키마) 검증 로직 (향후 확장용)
│   └── config.ts            # 환경 변수 및 디자인 시스템 상수 정의
└── styles/                  # Tailwind 또는 커스텀 CSS 파일
    └── globals.css         # Tailwind 설정 및 기본 스타일 정의
```
